모든 수치는 시뮬레이션 결과다. 실물 로봇 검증은 아직 하지 않았다. 시뮬레이터는 실제 SLAM 맵·로봇 반경·RC카 크기·로봇 간 충돌·덫의 물리적 포획을 반영하지만, 인식 지연·Nav2 경로 추종 오차·바퀴 미끄러짐은 반영하지 않는다. 아래 설계도는 이 가정 위에서의 로직 구조를 보여준다.

1. 메시지 인터페이스 — 노드 경계

herding_node.py:216–232

플랜 A와 달리 ~/robot1_goal도 발행한다 — 로봇 2대 모두 이 노드가 조종한다는 뜻. 좌표만 발행하고 Nav2 액션은 직접 호출하지 않는다(경로 추종은 Nav2·로봇 파트 담당).

2. 6+1 상태 FSM

state_machine.py:7–113

CORNER는 "포획 반경 안 + 도주확률 집중"일 때만 들어가고, 둘 중 하나라도 깨지면 즉시 HERD로 돌아간다 — 별도의 하강 조건이 없는 이유는 CORNER가 HERD 판정의 정확한 부정으로 정의되기 때문. 세 상태(TRACK/HERD/CORNER) 중 어디에 있든 관측이 3초 넘게 끊기면 상태와 무관하게 LOST로 덮어쓴다.

3. HerdingCore.step() 제어 플로우

herding_core.py:495–859

매 0.2초 한 번씩 실행된다. FSM 상태에 따라 세 갈래로 갈라지고, HERD·CORNER 갈래 안에서 다시 "포획존 근처에서 정체됐는가"로 갈라진다 — 이 마지막 분기의 YES 쪽(엔드게임 협공)이 로봇 B의 기여를 0에서 유의미한 수준(구조 14 : 역행 0, p=0.00012)으로 끌어올린 지점이며, 이 프로젝트가 존재하는 이유다.
