# UI 데이터 표시 분류 및 화면 구성 제안

작성일: 2026-08-11

## 1. 목적

운영 DB에 축적되는 데이터를 기준으로 System Monitor에서 무엇을 보여줄지 정하고,
실시간 관제와 이력·분석 화면의 정보 밀도를 나누기 위한 기준 문서다.

대분류는 다음 8개로 정한다.

1. 사건(Incident)
2. 탐지(Detection)
3. 쥐 이동경로(Rat Tracking)
4. 쥐구멍(Opening)
5. 덫(Trap)
6. 덫 점검(Trap Inspection)
7. 로봇 임무(Robot Mission)
8. 통계(Statistics)

## 2. 데이터 분류

### 2.1 사건(Incident)

한 번의 쥐 발견부터 포획 또는 유실로 종료될 때까지의 대응 단위다.

| 구분 | 표시 데이터 |
|---|---|
| 기본 | 사건 ID, 최초 발견 시간, 최초 발견 위치, 위험등급 |
| 결과 | 현재 상태(`CAPTURED` / `LOST`), 처리 결과, 종료 시간 |
| 계산값 | 발견부터 종료까지의 대응시간 |

목록 표현 예시: `INC-001 · 22:31 발생 · 포획 완료 · 대응 2분 35초`

진행 중 사건에는 종료 시간이나 대응 결과 대신 `진행 중`과 경과시간을 표시한다.

### 2.2 탐지(Detection)

센서 또는 탐지 모델이 객체를 발견한 개별 이벤트다.

| 구분 | 표시 데이터 |
|---|---|
| 탐지 | 탐지 시간, 객체 종류, 탐지 로봇, confidence |
| 위치 | Map X/Y |
| 증거 | 탐지 이미지가 있을 때 썸네일과 원본 보기 |

객체 종류는 현재 `RAT`, `OPENING`을 사용한다. `DROPPING`은 향후 항목으로
표시하되, 실제 파이프라인이 연결되기 전에는 운영 필터와 통계에서 숨기는 것을
권장한다.

### 2.3 쥐 이동경로(Rat Tracking)

Incident에 연결된 시간순 위치 기록이다.

| 필드 | 의미 |
|---|---|
| Timestamp | 위치가 기록된 시각 |
| X/Y | Map 좌표 |
| Confidence | 해당 시점 추적 신뢰도 |
| Incident | 경로가 속한 사건 |

UI에서는 점 목록보다 지도 위 선으로 표시한다. 최초 발견점, 현재/마지막 위치,
포획 또는 유실 위치는 서로 다른 마커로 강조하고, 경로 위 시간 탐색이 가능하면
탐지 이미지와 함께 동기화한다.

### 2.4 쥐구멍(Opening)

| 구분 | 표시 데이터 |
|---|---|
| 식별·위치 | Opening ID, X/Y |
| 발견·검증 | 최초/최근 발견시간, 최근 검증시간, 검증 횟수 |
| 상태 | `CANDIDATE`, `VERIFIED`, `MISSING`, `REVERIFY`, `SEALED` |

지도에서는 상태별 색이나 외곽선을 사용하고, 상세 패널에는 최근 검증 시각과
연결된 덫을 우선 표시한다. 목록 기본 정렬은 `REVERIFY` 우선, 최근 발견시간
내림차순이 적절하다.

### 2.5 덫(Trap)

| 구분 | 표시 데이터 |
|---|---|
| 기본 | Trap ID, 연결된 Opening, 설치 위치, 설치시간 |
| 상태 | `ACTIVE`, `MOVED`, `MISSING`, `CAPTURED` |
| 관리 | 최근 점검시간, 누적 포획수 |

현재 실제 시스템에서 판별 가능한 상태가 `ACTIVE`, `MOVED`라면 두 상태만 운영
상태로 노출한다. `MISSING`, `CAPTURED`는 신호가 연결되기 전까지 비활성 범례나
추정 상태로 만들지 않는다.

### 2.6 덫 점검(Trap Inspection)

| 구분 | 표시 데이터 |
|---|---|
| 점검 | 점검 시간, 점검 로봇, 결과 |
| 위치·거리 | 감지된 Trap X/Y, Opening과 Trap 사이 거리 |

목록 표현 예시:

```text
T001  08/08  Robot6  정상  0.06 m
T001  08/09  Robot6  이동  0.31 m
```

거리 임계값을 넘긴 기록은 수치와 행 전체를 경고색으로 표시한다. `OK`와
`MOVED`의 판정 임계값은 UI에 하드코딩하지 않고 API가 내려주는 결과를 따른다.

### 2.7 로봇 임무(Robot Mission)

| 구분 | 표시 데이터 |
|---|---|
| 로봇 | Robot4 / Robot6 |
| 역할 | `PATROL`, `TRACK`, `SWEEP`, `HERD`, `RETURN` |
| 수행 | 시작/종료시간, 수행시간, 성공/실패, 실패원인 |
| 연결 | 관련 Incident |

`DOCK`은 독립 임무로 만들지 않고 `RETURN` 상세 과정에 표시한다. 역할명과 현재
로봇 동작 상태는 의미가 다르므로 UI에서 각각 `임무`와 `현재 상태`로 구분한다.

### 2.8 통계(Statistics)

통계는 별도 원본 테이블을 요구하지 않고 위 데이터를 집계해 표시한다.

| 영역 | 지표 |
|---|---|
| 시간 | 시간대별 Rat 탐지 횟수, 최다 출몰 시간대 |
| 사건 | 월간 Incident 수, 포획 수, 유실 수, 포획 성공률, 평균 대응시간 |
| 로봇·알고리즘 | 평균 TRACK/HERD 시간, 로봇별 임무 수, 성공/실패 수 |
| 위험지역 | Rat 탐지, Opening, 향후 Dropping 위치의 지도 Hotspot |

표본 수가 적을 때 비율만 크게 보이면 오해하기 쉬우므로 성공률에는 항상
`성공 건수 / 종료 사건 수`를 함께 표시한다. 진행 중 사건은 성공률과 평균
대응시간의 분모에서 제외한다.

## 3. 권장 화면 정보 구조

8개 분류를 동일한 크기의 메뉴로 나누기보다 사용 목적에 따라 세 화면으로
묶는 것이 적절하다.

### 3.1 실시간 관제

운영자가 지금 조치해야 할 정보만 한 화면에 둔다.

1. **현재 Incident 요약**: 상태, 경과시간, 위험등급, 담당 로봇
2. **통합 지도**: 쥐 이동경로, Opening/Trap 위치와 상태, 로봇 현재 위치
3. **로봇 현재 상태**: 연결, 배터리, 현재 상태, 임무 역할, 마지막 수신시각
4. **최근 이벤트**: 탐지, 대상 유실, 덫 이동, 임무 실패 등 우선순위 높은 변화

지도 레이어는 `쥐 경로`, `Opening`, `Trap`, `Robot`을 각각 켜고 끌 수 있게 한다.
메인 화면에는 장기 통계 차트를 넣지 않고, 현재 사건이 없을 때만 최근 24시간
요약을 빈 상태 영역에 작게 보여준다.

### 3.2 자산·점검

Opening과 Trap은 사건 이력보다는 현장 관리 자산에 가깝기 때문에 하나의 화면에
묶는다.

- 지도와 Opening/Trap 목록을 함께 표시
- `REVERIFY`, `MOVED`, 장기 미점검 항목을 상단에 우선 표시
- Opening 선택 시 연결된 Trap과 최근 점검 기록 표시
- Trap 선택 시 설치 위치, Opening까지의 거리, 점검 이력 표시

### 3.3 이력·분석

- Incident History: 기간, 결과, 위험등급, 담당 로봇 필터
- Incident 상세: 탐지 목록, 쥐 이동경로, 관련 임무를 하나의 타임라인으로 결합
- Detection 분석: 시간대별 그래프와 지도 분포
- Robot Mission 성능: 역할별 수행시간과 성공/실패
- Trap Inspection History: 덫, 결과, 로봇, 기간 필터
- Hotspot: Rat과 Opening을 분리해서 보거나 겹쳐 보기

상세 페이지를 데이터 테이블별로 흩어 놓기보다 `Incident`를 중심으로 Detection,
Rat Track, Robot Mission을 연결하면 한 사건의 발견부터 종료까지 이해하기 쉽다.

## 4. 표시 우선순위

| 우선순위 | UI 항목 | 이유 |
|---|---|---|
| P0 | 로봇 연결·상태·위치, 현재 Incident, Rat 경로 | 즉시 대응에 필요 |
| P0 | Opening/Trap 위치와 실제 판별 가능한 상태 | 점검·대응 위치 판단에 필요 |
| P1 | Incident 목록/상세, Detection 이력, Trap 점검 이력 | 사후 확인과 운영 관리에 필요 |
| P1 | Robot Mission 이력과 실패 원인 | 알고리즘·로봇 성능 확인에 필요 |
| P2 | 시간대 그래프, 성공률, 평균 대응시간, Hotspot | 충분한 표본이 쌓인 뒤 의미가 커짐 |
| 보류 | Dropping 통계, Trap `MISSING`/`CAPTURED` 자동 상태 | 실제 입력 신호가 아직 없음 |

## 5. 카드와 상세 패널 권장값

실시간 화면의 카드에는 빠르게 판단할 수 있는 값만 둔다.

| 카드 | 항상 표시 | 상세에서 표시 |
|---|---|---|
| Incident | ID, 상태, 발생 후 경과시간, 위험등급 | 좌표, 종료시간, 대응시간, 관련 탐지·임무 |
| Robot | ID, 연결, 배터리, 상태, 현재 역할 | 위치, 마지막 수신, 임무 시작시간, 실패원인 |
| Opening | ID, 상태, 최근 검증시간 | 최초/최근 발견, 검증 횟수, 연결 Trap |
| Trap | ID, 상태, 최근 점검시간 | 설치시간, 누적 포획수, 거리와 점검 이력 |
| Detection | 종류, 시간, 로봇, confidence | 좌표, 이미지, 관련 Incident |

좌표 원시값은 카드 전면보다 지도와 상세 패널에서 보여주는 것이 좋다. 시간은
실시간에서는 `3분 전`처럼 상대시간을 먼저, 상세에서는 절대시각을 함께 표시한다.

## 6. 상태와 결측값 표시 원칙

- 실제 신호가 없는 상태를 UI가 추론해 확정 상태로 만들지 않는다.
- 값이 없으면 `0`, `정상` 대신 `미수신` 또는 `—`를 사용한다.
- 실시간 데이터가 오래됐으면 값은 유지하되 `마지막 수신 N초 전`과 `STALE`을 표시한다.
- `CAPTURED`와 `LOST`는 색뿐 아니라 텍스트와 아이콘을 함께 사용한다.
- confidence는 백분율로 표시하되 운영 결과나 위험등급과 같은 의미로 사용하지 않는다.
- 상태 원문 enum은 API에서 유지하고, UI가 한국어 라벨로 변환한다.
- 지도 좌표계가 `map`이 아닐 경우 동일 지도에 합쳐 그리지 않고 좌표 미확정으로 표시한다.

## 7. 현재 저장소 구현과의 차이

이 문서의 7개 원본 테이블은 목표 운영 데이터 모델로 취급해야 한다. 2026-08-11
현재 이 저장소에서 확인되는 영속 데이터는 다음과 같다.

| 위치 | 현재 테이블 | 현재 가능한 표시 |
|---|---|---|
| `Sysmon/backend/system_monitor/history_store.py` | `detections`, `trail_points` | 탐지 목록·사진, 로봇 이동 경로 |
| `src/turtle_project/turtle_project/db_node.py` | `holes` | 구멍 좌표, 덫 설치 여부 |

현재 실시간 화면은 서버 메모리의 로봇·탐지·임무 상태도 표시하지만 재시작 후의
영구 이력은 아니다. 따라서 Incident, Rat Track, Opening, Trap, Trap Inspection,
Robot Mission 7개 테이블을 UI에 연결하려면 DB 조회 API 계약이 먼저 필요하다.
UI가 SQLite 파일을 직접 읽기보다 백엔드 API를 통해 조회하는 방식을 권장한다.

## 8. UI 연동 전에 확정할 API 최소 계약

1. Incident 목록/상세와 진행 중 Incident 조회
2. Incident별 Detection과 Rat Track 시간순 조회
3. Opening/Trap 목록, 상태, 연결 관계 조회
4. Trap별 Inspection 이력 조회
5. Incident 및 Robot별 Mission 이력 조회
6. 기간과 현장 시간대 기준을 받는 통계 집계 조회
7. 모든 응답의 ID, timestamp 형식, enum, 좌표 frame 규칙

시간은 DB에서 UTC 기준으로 저장·전송하고 UI에서 현장 시간대로 변환한다. 통계
기간 경계와 월간 집계도 같은 시간대 규칙을 사용해야 한다.

## 9. 구현 권장 순서

1. 현재 실시간 관제에 Incident 요약과 지도 레이어를 연결한다.
2. Incident 목록과 상세 타임라인을 만든다.
3. Opening/Trap 자산·점검 화면을 만든다.
4. Robot Mission 이력을 Incident 상세에 연결한다.
5. 데이터가 충분히 쌓인 뒤 통계와 Hotspot을 추가한다.

첫 배포의 완료 기준은 운영자가 한 화면에서 `무슨 사건이 진행 중인지`, `쥐와
로봇이 어디에 있는지`, `어느 Opening/Trap에 문제가 있는지`를 확인할 수 있고,
종료된 사건 하나를 선택해 발견부터 포획/유실까지 재구성할 수 있는 것이다.
