## 한 문장 사업 정의

Under-Guard는 식품 제조·물류시설에서 고정형 트랩과 전문기사 방문만으로 지속 확인하기 어려운 랙·팔레트·설비 하부를 반복 점검하고, 설치류·침입구 후보·배설물 흔적을 증거화해 조기 대응과 감사 대응을 정밀화하는 두 대 기반 이동형 위험관리 RaaS다.

기존 방제업체를 대체하는 포획 로봇으로 판매하지 않는다. 기존 IPM 위에 방문 사이의 시간 공백, 트랩 사이의 연속 공간 공백, 분산된 증거의 데이터 공백을 보완하는 이동형 관찰·증거 계층으로 포지셔닝한다.

## 초기 고객

Beachhead Customer는 사각지대와 야간 무인지역이 많고 HACCP·고객사·글로벌 식품안전 감사로 인해 설치류 사고비용이 큰 대형 식품 제조공장과 식품 물류센터다.

우선 고객군은 다음과 같다.

1. 식품 제조공장, 식품 물류센터
2. 냉장·냉동창고, 대형 유통창고
3. 제약·건기식·화장품 시설

주요 구매자는 공장장·센터장, 품질/HACCP 담당, 시설관리, 운영 및 리스크관리 담당자다. 반복 목격, 감사 지적, 도크 침입 흔적, 트랩 증가, 신규 라인·창고 확장 등이 구매 트리거가 된다.

## 고객이 구매하는 결과

- 사고 이전 조기 발견
- 출몰 원인과 대응 우선순위 특정
- 순찰·발견·판단·조치·재검증의 증거
- 야간 사각지대와 방문 공백 축소
- 트랩과 전문기사의 우선 점검 효율 향상
- 감사·고객사 대응용 통합 보고

## 세 가지 위험신호

| 위험신호 | 사업 의미 | 필요한 결과 | 후속 책임주체 |
|---|---|---|---|
| 살아 있는 설치류 | 즉시 대응이 필요한 Critical Incident | 시각·구역·이동방향·마지막 위치·추적 증거·알림 | 시설 관리자·전문 방제기사 |
| 침입구·은신처 후보 | 재발 원인과 구조적 취약점 | 위치·이미지·기존 봉쇄/트랩 여부·보수 요청·재검증 | 시설관리·방제업체 |
| 배설물·오염 흔적 | 과거 또는 반복 활동의 증거 | 오염 의심구역·시각·주변 재순찰·세척/샘플링 요청 | 품질/HACCP·위생팀 |

세 신호는 개별 Detection으로 끝내지 않고 `발견 → 원인 후보 → 조치 → 재검증`을 하나의 사건으로 연결해야 한다. 탐지 실패와 표적 유실도 다음 점검 우선순위를 만드는 데이터로 보존한다.

## 서비스 운영 흐름

### 평시

1. 관리구역·중요자산·트랩·침입구 후보 온보딩
2. 두 대를 이용한 연속 순찰과 중요 점검지점 확인
3. 설치류·침입구·배설물의 시간·구역·이미지 증거 수집
4. 반복 빈도·구역 중요도·트랩 상태 기반 우선순위 판단
5. 조치 후 동일 구역 재검증과 보고

### 사고 발생 시

- 관찰 로봇: 설치류 활동구역·이동방향·마지막 위치 기록
- 확인 로봇: 등록 트랩과 침입구의 설치·활성·봉쇄 상태 우선 확인
- 관리자: 증거를 보고 트랩·봉쇄·기사 출동 승인
- 후속 서비스: 조치 구역 재순찰과 사건 종결 증거 기록

두 대 운영은 충전·점검·고장 시 순찰 공백을 줄이고, 사고 시 관찰과 주변 확인을 병행하며, 한 번의 유실을 사건 종료가 아닌 후속 확인 우선순위로 바꾸는 것이 핵심 가치다.

## Pilot 수락 기준

| 검증영역 | 초기 목표 |
|---|---|
| 중요 점검지점 확인률 / 순찰 가용률 | 90% / 95% |
| 기존 방식보다 선행 발견 | 60% 이상 목표 |
| 비설치류·중복 경보 검토 부담 | 8시간당 1건 이하 목표 |
| 유효 사건 필수 증거 포함률 | 100% |
| 발견부터 관리자 판단·우선 점검까지의 시간 | 기존 방식 대비 30% 단축 |
| 관찰과 트랩·침입구 확인의 병행 성공률 | 80% 이상 목표 |
| 야간 하부·트랩 단순 점검시간 | 50% 이상 감소 목표 |
| 기사 현장시간 | 30% 이상 감소 목표 |
| 주간·월간·사건 보고서 작성 | 5분 이내 |
| 연간 환산 편익/구독료 | 1.5배 이상 목표 |
| Pilot 후 유료계약 의향 | 60% 이상 목표 |

30일 Pilot은 단일 식품공장 또는 물류센터의 중요 점검지점 20~50개를 대상으로 야간·비가동 시간을 포함한다. 기존 트랩과 기사 프로세스는 유지하고 Under-Guard를 추가해 비교한다. 교육·검증 단계에서는 살아 있는 설치류 대신 RC 이동체·모형·녹화자료임을 명확하게 표시한다.

Go 조건은 커버리지·증거·점검시간 편익을 확인하고 최소 2개 고객의 유료 Pilot 또는 금액 명시 LOI를 확보하는 것이다.

## RaaS와 가격 가정

운영사는 두 대 배치, 현장 설정, 원격 관제, 보고, 정기점검, 고장 대응과 기존 방제업체 연계를 제공한다. 고객은 로봇 CAPEX와 전담 운영인력을 직접 부담하지 않고 월 기본료와 선택 옵션을 지불한다.

| 상품 | 배치원가 | 월 구독료 | 월 운영비 | 단순 회수기간 |
|---|---:|---:|---:|---:|
| Pilot | 1,800만원 | 179만원 | 60만원 | 15.1개월 |
| Standard | 2,400만원 | 249만원 | 80만원 | 14.2개월 |
| Industrial | 3,000만원 | 299만원 | 100만원 | 15.1개월 |

이 가격은 시장가격이 아니라 사업성 검토용 **팀 가정**이다. 유료 Pilot과 고객 인터뷰 전에는 확정 가격이나 시장 수용 가격으로 표현하지 않는다.

## 책임과 주장 경계

- 초기 상품은 포획이 아니라 탐지·증거·대응 조정 서비스다.
- 실제 트랩 배치, 포획 개체 수거, 소독, 살서제 사용, 시설 봉쇄 공사는 전문 방제업체·위생팀·시설팀 책임으로 분리한다.
- 트랩·봉쇄·기사 호출 등 현장 조치는 관리자 승인과 책임주체를 기록해야 한다.
- 오탐·미탐은 관리자 검토, 사건등급, 서비스 SLA로 책임범위를 명시한다.
- 영상 촬영구역·보관기간·권한·목적은 계약과 개인정보 정책에서 관리한다.
- 경쟁사 성능, 시장 통계, 극단 손실 사례를 Under-Guard의 성능이나 평균 고객 ROI로 전용하지 않는다.

## 개발 판단 원칙

1. 기능 추가 시 어떤 BR과 Pilot KPI를 지원하는지 기록한다.
2. ROS·SLAM·AI 구현 세부는 이 문서가 아닌 별도 System Requirements에 정의한다.
3. Detection만 늘리기보다 사건, 승인, 조치, 재검증의 연결을 우선한다.
4. 교육용 Mock과 실제 현장 데이터를 UI·DB·보고서에서 명확히 구분한다.
5. 실제 포획·트랩 작동·시설 조치는 책임주체와 안전정책이 확정되기 전까지 자동 실행하지 않는다.
